环境准备

  • 操作系统：Windows（推荐 Windows 10+）
  • Python：3.8 及以上
  • 依赖包：Jinja2 + PyYAML
# 安装依赖（只需执行一次）
pip install jinja2 pyyaml

# 验证安装
python -c "import jinja2, yaml; print('OK')"

步骤一：准备 WSDL 文件

获取目标接口的 WSDL 文件，可以来自：

  • 接口提供方给的 WSDL URL，浏览器打开后另存为 .wsdl 文件
  • 已有的 OSB 项目中导出的 WSDL
  • SoapUI / Postman 等工具导出的 WSDL
提示：WSDL 文件放在项目目录外的任意位置即可，配置中通过 source_path 指定路径（支持相对路径和绝对路径）。

步骤二：编写 config.yaml

完整配置示例

global:
  module_path: YlglSB/Ylgl/Workflow        # 目标模块路径

defaults:
  pipeline_template: CommonSB/Hmw/PipelineTemplates/HspPptSoapEsbInfo
  http:
    timeout: 0
    connection_timeout: 0
    retry_count: 0
    retry_interval: 30
    load_balancing: round-robin

project:
  application_name: YlglSB
  package_prefix: com.hand.hsp

services:
  - name: YlglWorkflowReturnSoap
    type: http
    wsdl:
      source_path: ../wsdls/OaWebService.WSDL
      binding_name: OaWebServiceSoapBinding
      namespace: http://server.webservice.jtg.com
      port_name: OaWebService
    security:
      provider_id: XACMLAuthorizer
    endpoint:
      uri: http://192.168.61.150:8080/ylgl/services/OaWebService
    operations:
      - name: workflowBack
    business_service_name: YlglWorkflowReturnSoapBiz

配置字段说明

字段路径 必填 说明 如何获取
global.module_path 可选 目标 OSB 模块路径 看已有项目的路径结构，不填则用服务名
project.application_name 必填 OSB 应用名称 看已有项目，如 YlglSB
services[].name 必填 服务名称 自定义，通常与 WSDL 的 service 名一致
services[].type 必填 服务类型：http / db_adapter / jms / file HTTP/SOAP 接口填 http
wsdl.source_path 必填 WSDL 文件路径 指向 WSDL 文件的相对或绝对路径
wsdl.binding_name 可选 WSDL binding 名称 WSDL 文件中 <wsdl:binding name="...">
wsdl.namespace 可选 WSDL 目标命名空间 WSDL 文件中 targetNamespace="..."
wsdl.port_name 可选 WSDL port 名称 WSDL 文件中 <wsdl:port name="...">
security.provider_id 可选 安全策略提供者 通常填 XACMLAuthorizer
endpoint.uri 必填 后端服务实际地址 问接口提供方获取
operations[].name 可选 操作名称 WSDL 中 <wsdl:operation name="...">，多个用列表
business_service_name 可选 Business Service 自定义名称 不填则用 name

从 WSDL 文件提取配置

打开 WSDL 文件，找到以下关键信息：

<?xml version="1.0" encoding="UTF-8"?>
<wsdl:definitions
    targetNamespace="http://server.webservice.jtg.com"   ← wsdl.namespace
    ...>

    <wsdl:binding name="OaWebServiceSoapBinding" ...>      ← wsdl.binding_name
        ...
        <wsdl:operation name="workflowBack">                  ← operations[].name
            ...
        </wsdl:operation>
    </wsdl:binding>

    <wsdl:service name="OaWebService">
        <wsdl:port name="OaWebService" ...>                   ← wsdl.port_name
            <wsdlsoap:address
                location="http://...:8080/ylgl/services/OaWebService"/> ← endpoint.uri
        </wsdl:port>
    </wsdl:service>
</wsdl:definitions>

步骤三：运行生成

# 在项目目录执行
cd osb-auto-config

# 基本用法
python python/generate_project.py config.yaml

# 指定输出目录
python python/generate_project.py config.yaml generated_projects

# 输出结构
generated_projects/
└── YlglSB/                              ← application_name
    └── YlglWorkflowReturnSoapSB/        ← {服务名}SB
        ├── BusinessServices/
        │   └── YlglWorkflowReturnSoapBiz.BusinessService
        ├── Pipelines/
        │   └── YlglWorkflowReturnSoapPP.Pipeline
        ├── ProxyServices/
        │   └── YlglWorkflowReturnSoapProxy.ProxyService
        ├── WSDLs/
        │   └── OaWebService.WSDL
        ├── Adapters/                    ← HTTP 类型不使用
        ├── Schemas/                     ← 空目录
        └── Transformations/             ← 空目录
多服务批量生成：在 services 列表里加多个服务，脚本会自动为每个服务生成独立项目，一次性全部完成。

步骤四：导入 OSB

  1. 打开 Oracle JDeveloper，打开 OSB 项目
  2. 将生成的 4 个文件（.BusinessService、.Pipeline、.ProxyService、.WSDL）复制到对应项目的目录中
  3. 保存并部署到 WebLogic 即可

常见问题

Q: 生成的文件导入 OSB 报错了？

检查 config.yaml 中的 module_path 是否与实际 OSB 项目的模块路径一致。不一致会导致内部引用路径错误。

Q: WSDL 文件已经是 OSB 格式了？

工具会自动检测。如果 WSDL 文件已包含 <con:wsdlEntry> 标签，会直接复制；否则自动用 CDATA 包裹。

Q: 一个接口有多个 operation 怎么办？

当前一个 Pipeline 只配置第一个 operation。如需多个 operation，在 operations 列表里列出来，每个 service 配置一个 operation，共用同一个 WSDL 和 endpoint。

Q: 如何修改默认超时/重试配置？

在 defaults.http 段修改全局默认值，或在具体服务的 endpoint 段覆盖。

Q: 生成的产物和人工配置有什么区别？

经过逐行对比，XML 结构、命名空间、配置段完全一致。唯一的差异是我们修复了人工产物中的拼写错误（session-sctikiness → session-stickiness）。
